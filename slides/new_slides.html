The Challenge

  • To play audio we need an analog signal. But, bare metal, the gpio can only output digital levels: 0 and 3.3V .
  • Available: GPIO, PWM, DMA, Interrupts.
  • Goal: produce recognizable music from a single digital pin using interrupts, and memory optimization.
Core problem: how do we turn a 1-bit digital output into something that sounds like analog audio?

DMAReads PDM words from memory and writes them to the PWM FIFO — no CPU involved.

Why DMA Is Necessary

What the CPU would have to do

  • Toggle GPIO for every PDM bit
  • Meet a bit rate of 1.4112 MHz which is impossible for the CPU
  • That is one output update every ~709 ns
bit_period = 1 / 1,411,200 ~= 709 ns
DMA is used to stream PDM audio data to the PWM hardware without CPU involvement. DMA solves this by streaming memory directly to the GPIO peripheral with deterministic hardware timing. The DMA is paced by the PWM to move at a (high) given frequency the data to gpio.

Why is PWM necessary ? Clocking and Timing

PWM is used here as a hardware pacing source for DMA, not as the audio signal itself.

PLLD clock: 500 MHz Clock divider: 44.29 PWM clock: 11.2896 MHz Oversampling: 32x Audio sample rate: 11.2896 MHz / 32 = 44.1 kHz
  • Target audio rate: 44,100 samples/second
  • Target bit rate: 44,100 × 32 = 1,411,200 bits/second
  • If timing is off, the pitch and audio quality are wrong
This is why getting the divisor chain right mattered so much: a 4× timing mistake makes the audio obviously wrong.
